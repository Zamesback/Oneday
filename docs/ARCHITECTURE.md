## 2. 路由表

| 路由 | 视图 | 说明 |
|---|---|---|
| `#/dashboard` 或 `#/` | 仪表盘 | 默认首页 |
| `#/customers` | 客户列表 | 搜索、筛选、卡片网格 |
| `#/projects` | 项目列表 | 搜索、筛选、行列表 |
| `#/kanban` | 销售看板 | 按阶段分列 |
| `#/settings` | 设置 | 阶段管理、数据管理 |

### 详情 Drawer（非路由，全局覆盖层）

| 触发 | Drawer 内容 | Tab |
|---|---|---|
| 点击客户卡片 | 客户详情 | 基本信息 / 需求 / 关联项目 / 沟通记录 |
| 点击项目行/卡片 | 项目详情 | 基本信息 / 进展 / 里程碑 / 沟通记录 |

Drawer 不改变 URL，通过 JS 状态控制显示/隐藏。

## 3. 视图详细设计

### 3.1 仪表盘 `#/dashboard`

**顶部区域：**
- 问候语（根据时间：早上好/下午好/晚上好）
- 副标题：今日待跟进数 + 待推进项目数
- 右侧：「新增记录」按钮（快速添加沟通记录）

**统计卡（4 列）：**
1. 跟进中客户数（从 customers 实时计算 status=following）
2. 进行中项目数（从 projects 实时计算 stage≠won/lost）
3. 今日待办数（从 activities 筛选今日 + 未完成）
4. 本月预计成交（从 projects 筛选 stage=proposal + amount 求和）

**下方两栏：**
- 左：今日待跟进列表（优先级排序，可勾选完成）
- 右：近期沟通时间线（最近 7 天，按时间倒序）

### 3.2 客户列表 `#/customers`

**工具栏：**
- 搜索框（姓名/公司/邮箱模糊搜索）
- 筛选 chip：全部 / 线索 / 跟进中 / 已成交 / 已流失
- 右侧：「新增客户」按钮

**内容区：**
- 客户卡片网格（2 列）
- 每张卡片：姓名、公司+职位、状态标签、需求摘要、最近联系时间
- 点击卡片 → 打开客户详情 Drawer

### 3.3 项目列表 `#/projects`

**工具栏：**
- 搜索框（项目名/客户名模糊搜索）
- 筛选 chip：全部 / 按阶段 / 按优先级
- 右侧：「新增项目」按钮

**内容区：**
- 项目行列表（每行一个项目）
- 每行：优先级圆点、项目名、客户名、阶段标签、进度条、金额、截止日期
- 点击行 → 打开项目详情 Drawer

### 3.4 销售看板 `#/kanban`

**列（按 settings.stages 顺序）：**
- 线索 / 跟进中 / 提案谈判 / 已成交 / 已流失
- 每列顶部：阶段名 + 项目计数

**卡片：**
- 项目名、客户名、金额、优先级（灰度圆点）
- 点击卡片 → 打开项目详情 Drawer
- 卡片内或详情内可切换阶段（下拉选择）

### 3.5 设置 `#/settings`

**分区：**
1. 销售阶段管理：列表展示，可增删改、上下移动排序
2. 数据管理：导出 JSON、导入 JSON、清空数据（二次确认）
3. 关于：版本号、数据存储说明

## 4. 详情 Drawer 设计

### 4.1 客户详情 Drawer

**宽度：** 480px，从右侧滑入

**头部：**
- 客户姓名（大标题）
- 公司 + 职位（副标题）
- 状态标签
- 关闭按钮

**Tab 切换：**

| Tab | 内容 |
|---|---|
| 基本信息 | 姓名、公司、职位、电话、邮箱、来源、地址（均可编辑） |
| 需求 | 需求描述、预算、备注（可编辑） |
| 关联项目 | 该客户的项目列表（点击跳项目详情） |
| 沟通记录 | 沟通记录时间线 + 「新增记录」按钮 |

### 4.2 项目详情 Drawer

**宽度：** 480px，从右侧滑入

**头部：**
- 项目名（大标题）
- 客户名（副标题，点击跳客户详情）
- 阶段 + 优先级标签
- 关闭按钮

**Tab 切换：**

| Tab | 内容 |
|---|---|
| 基本信息 | 项目名、客户、阶段（下拉）、优先级（下拉）、金额、截止日期、进度（可编辑） |
| 进展 | 项目描述、下一步行动（可编辑） |
| 里程碑 | 里程碑列表，可勾选完成、新增、删除 |
| 沟通记录 | 沟通记录时间线 + 「新增记录」按钮 |

| 组件 | 用途 | 触发 |
|---|---|---|
| 新增客户模态框 | 新增客户 | 客户列表页「新增客户」按钮 |

## 6. 状态管理

### 全局状态对象

```javascript
const state = {
  currentRoute: 'dashboard',     // 当前路由
  drawer: {
    type: null,                   // 'customer' | 'project' | null
    id: null,                     // 客户/项目 ID
    tab: 'info'                   // 当前 Tab
  },
  modal: {
    type: null,                   // 'new-customer' | 'new-project' | 'new-activity' | null
    data: null                    // 预填数据
  },
  filters: {
    customers: 'all',             // 客户筛选状态
    projects: 'all'               // 项目筛选状态
  },
  search: {
    customers: '',                // 客户搜索关键词
    projects: ''                  // 项目搜索关键词
  },
  toast: null                     // 当前 Toast 消息
}
```

### 数据流

```
用户操作 → 更新 state → 调用 store 持久化 → 重渲染受影响区域
```

---

## 7. 视图切换机制

- 使用 `location.hash` + `hashchange` 事件
- 路由变化时：更新 `state.currentRoute`，重渲染主内容区
- 侧边栏激活态根据 `state.currentRoute` 自动更新
- 初始加载时读取 hash，无 hash 时默认 `#/dashboard`

## 8. 文件结构（单文件）

```
index.html
├── <head>
│   ├── <meta> 视口设置
│   └── <style> 全部 CSS（按区域分段注释）
├── <body>
│   ├── 标题栏
│   ├── 侧边栏
│   ├── 主内容区（5 个视图容器，按路由显示/隐藏）
│   ├── Drawer 容器（客户详情 / 项目详情）
│   ├── 模态框容器
│   ├── Toast 容器
│   └── <script> 全部 JS
│       ├── 数据层（store：localStorage CRUD）
│       ├── 状态管理（state + 渲染函数）
│       ├── 路由（hash 监听）
│       ├── 组件渲染（各视图 + Drawer + 模态框）
│       ├── 事件绑定
│       └── 初始化（加载数据 + 渲染）
```
